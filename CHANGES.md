# Changes in orabooster-epplus

## 4.5.3.8-ora.5 (not released yet, OraScope Co.,Ltd.)

The B items of the candidate list in #8, taken one at a time. They only add: a workbook that does not use them is saved exactly as by ora.4 (the samples of `tools/SaveBench` are compared part by part at every merge).

- **#32 (B6)** The export of a range: the reverse of `LoadFromDataTable` and `LoadFromText`. New file `EPPlus/ExcelRangeBase.Export.cs`; `ExcelRangeBase` is `partial` for it. Nothing here changes the workbook.
  - `range.ToDataTable(firstRowIsHeader = true)`: a `DataTable` named after the sheet. A column is typed when all its values have one type (`double`, `DateTime`, `bool`, `string`, `TimeSpan`), `object` when they are mixed, `string` when it has none. A number in a cell with a date format is a `DateTime`. An empty header is `Column` and its position, a header that comes again gets `_2`, `_3`.
  - `range.ToText(format = null)` and `range.SaveToText(file, format = null)`: delimited text (RFC 4180) with the `ExcelTextFormat` of `LoadFromText`: delimiter, text qualifier, end of line, culture. Numbers have all their digits, dates are `yyyy-MM-dd` or `yyyy-MM-dd HH:mm:ss`, booleans `TRUE` and `FALSE`. A value is qualified when it has the delimiter, the qualifier (doubled), a line break or a space at an end in it, and also when it is a text that would be read as a number or a date (`00123`, `1e5`, `2026-01-02`), so that `LoadFromText` with the same format gives the same values. With no text qualifier in the format, the double quote is used where one is needed. `SaveToText` with no format writes UTF-8 with a byte order mark (Excel reads it right); with a format it uses the encoding of the format.
  - `range.ToJson(firstRowIsHeader = true)`: a JSON array (RFC 8259) of objects named by the first row, or of arrays. Numbers with all their digits, `true`, `false`, `null`, dates as text `yyyy-MM-ddTHH:mm:ss`. Written by hand: the library has no JSON dependency.
  - `range.ToHtml(firstRowIsHeader = true)`: a `table` with the text of every cell as Excel shows it (escaped, a line break is `br`), merged cells as `colspan` and `rowspan`, numbers and dates to the right, bold and italic. No colours, borders or widths.
  - A range of whole rows or columns ends at the last row and column of the sheet that has a cell. A range with several areas gives its first area.
  - Checked in Excel 16: `issue32_export.csv` of `SaveBench issues` opens with the cells of `issue32_export.xlsx`: Korean text, a comma, a quote and a line break inside a cell, numbers, dates. Excel itself turns the quoted `"00123"` into the number 123, as it does with any CSV; `LoadFromText` keeps it a text.
  - Tests: 5 new (`Range_to_...`, `Range_is_saved_...`): column types and names, a round trip through `LoadFromText` in two cultures, the encoding of the file, a parse with `System.Text.Json`, the HTML text. Whole suite: 1,207 passed, 0 failed, 214 skipped. `charts`, `variety`, `keep` and the thirteen issue samples that were there before are part by part the same.
- **#34 (B5)** Saving and loading with asynchronous input and output. New file `EPPlus/ExcelPackage.Async.cs`; `ExcelPackage` is `partial` for it.
  - `SaveAsync()`, `SaveAsAsync(FileInfo)`, `SaveAsAsync(Stream)`, `LoadAsync(Stream)`, `LoadAsync(FileInfo)`, each also with a password, all with a `CancellationToken`. They do what `Save`, `SaveAs`, `Load` and `new ExcelPackage(file)` do.
  - **What is asynchronous:** every read from and write to the stream or file of the caller. A stream that does not allow synchronous writes (the response of an ASP.NET Core server) can be saved to, and a slow disk or network holds no thread. `SaveAs(stream)` and `Load(stream)` cannot use such a stream.
  - **What is not:** making the package. The parts are written and compressed in memory on the calling thread, as `Save` does it, and a loaded package is opened from memory. The library starts no threads; a program that must not wait for that (a window) can run the call on another thread itself. The documentation of the methods says so.
  - A package made over a stream of the caller (`new ExcelPackage(stream)`) is written to that stream asynchronously too; `SaveAsAsync(other)` writes both, as `SaveAs` does. A cancelled token stops the save before anything is made or written.
  - The saved package is the one the synchronous methods save: the tests compare every part.
  - Tests: 3 new (`Async_...`): a stream that throws on every synchronous read, write and flush; a file, loaded, changed and saved back; passwords; a package made over a stream; an error for a file that cannot be written; cancelling. Whole suite: 1,211 passed, 0 failed, 214 skipped. The samples of `SaveBench` that were there before are part by part the same.

New file `EPPlus/Table/PivotTable/ExcelPivotTableCalculatedField.cs`; `ExcelPivotTableFieldCollection` and `ExcelPivotTableField` are `partial` for it. Written from ECMA-376 Part 1 (18.10.1.3 `cacheField`, 18.10.1.69 `pivotField`) and a workbook Excel made. B2 of #8 is taken in parts: calculated fields, sorting by a data field, filters, slicers of pivot tables.
  - `pivotTable.Fields.AddCalculatedField(name, formula)` gives a field whose value is a formula of other fields (`Sales*2`, `Sales/Qty`; the equal sign is optional); `pivotTable.DataFields.Add(field)` shows it. On a field: `IsCalculated` and `Formula` (settable for a calculated field).
  - In the file, as Excel writes it: a cache field with the formula and `databaseField="0"` after the fields of the source, and a pivot field for it (`dragToRow="0" dragToCol="0" dragToPage="0" defaultSubtotal="0"`). The cache gets `refreshOnLoad="1"`: Excel works the values out when it opens the workbook.
  - Every pivot table of the cache gets the field: a workbook Excel made can have several pivot tables on one cache, and each of them needs a pivot field for every cache field.
  - A calculated field can only be a data field: adding it to the rows, columns or page fields throws. A name that a field of the pivot table has (case does not matter) is refused, and so is a formula that names a field the pivot table does not have, or the calculated field itself: Excel does not open a workbook with such a formula (tried). Names in single quotes, functions, numbers and texts in double quotes are told apart.
  - Calculated fields of a loaded workbook are read (`IsCalculated`, `Formula`).
  - Checked in Excel 16 (`tools/SaveBench/pivot-in-excel.ps1`, new: the pivot tables as Excel shows them after the refresh): `issue54_pivot_calculated.xlsx` of `SaveBench issues` opens without a repair with the calculated fields `Double =Sales*2` and `Per unit =Sales/Qty`, and the values North 80, 160, 10 to the total 440, 880, 10. - **#38 (B3)** Table styles that are defined in the workbook (custom table styles). New file `EPPlus/Table/ExcelCustomTableStyle.cs`; hooks in `EPPlus/ExcelStyles.cs`.
